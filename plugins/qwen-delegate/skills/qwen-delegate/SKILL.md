# Qwen 위임

사내 Qwen 에게 작업을 맡긴다. 이 대화에서는 **브리프만 쓰고**, Qwen 실행·검증은 `qwen-delegate:qwen-worker` 서브에이전트(Sonnet)가 한다. Qwen 보고서와 검증용 파일 읽기가 이 대화의 컨텍스트에 쌓이지 않게 하려는 구조다 — 이 대화에서 `delegate.mjs` 를 직접 돌리지 않는다.

## 1. 맡길지 정한다

위임의 목적은 **Claude 토큰 절약**이다. 맡기는 조건은 하나다:

> 직접 하면 쓸 토큰 > 위임 고정비(서브에이전트 기동 약 4.5만 Sonnet 토큰 + 브리프) + 결과 검증 토큰

Qwen 이 대신 쓰는 토큰(실측, 1건당): 리뷰 22~28턴·누적 입력 69만~211만·출력 2~4만, medium 구현 51턴·누적 입력 222만·출력 4.5만. 직접 했다면 턴은 더 적었겠지만 같은 크기의 탐색이다.

맡기는 일 — 읽을 것은 많고 결과는 싸게 확인되는 일:

| 종류 | 상한 | 검증이 싼 이유 |
|---|---|---|
| 리뷰 | 대상과 시나리오를 정해 줄 수 있으면 함수 1개부터 5~6 파일과 관련 SQL 추적까지 (실측 3건 모두 실제 버그 적중) | 지적이 file:line 으로 와서 그 자리만 열면 된다 |
| 구현 | 명세가 분명하고 로컬에서 돌릴 수 있는 수용 시험이 있는 1~2 파일, `medium` | 시험이 곧 검증이다. diff 가 작아야 검증 토큰이 작다 |
| 탐색 | "X 가 어디서 쓰이나", 모듈 구조 요약 | 답이 짧다 |

맡기지 않고 직접 하는 일 — 아끼는 토큰보다 위임 비용이 큰 일:
- 직접 하면 도구 호출 몇 번이면 끝나는 일 — 고정비 4.5만이 더 크다. 기준은 대략 "파일 여러 개를 읽고 도구를 10번 넘게 부를 일인가"
- 검증이 다시 하는 것과 같은 일 — "모듈 전체 검토"처럼 열린 리뷰(먼저 사용자와 범위를 좁힌다), 설계 결정, 보안의 최종 판정
- Qwen 이 확인할 수 없어 결국 다시 해야 하는 일 — DB·통합 환경·비밀값·실행 중인 서비스가 필요한 확인
- 고쳐 쓰는 토큰이 드는 일 — 레포 관례가 중요한 글(ADR·문서·화면 문구). 용어 규칙을 모르고 다른 문자가 섞일 수 있다
- 3 파일 이상에 걸친 구현 — diff 가 커서 검증이 비싸고, 1 파일 구현도 Qwen 컨텍스트를 94% 까지 썼다. 하려면 파일 단위로 쪼개 넘긴다

시간은 기준이 아니다. 위임은 5~45분 걸리지만 백그라운드로 돌고 그동안 다른 일을 한다.

## 2. 브리프를 쓴다

서브에이전트와 Qwen 은 이 대화를 보지 못한다. 대화에서 알게 된 것을 브리프에 담는다:
- 절대 경로 작업 디렉토리, 모드(`review` 또는 `implement`)
- 대상 파일·함수와 그 값이 어디에 쓰이는지
- 검토할 시나리오("어떤 상황에서 무엇이 틀릴 수 있나") 또는 구현 명세와 제약 — 실측에서 이 한 줄이 적중률을 갈랐다
- 구현이면 수용 기준, 돌릴 시험 명령, 격리된 worktree 경로(없으면 먼저 만든다. 같은 체크아웃에 쓰는 작업자를 둘 두지 않는다)
- 보고 언어
- 난이도 판단: 결함을 찾는 리뷰·파일 간 추적·동시성·보안이면 `xhigh`, 구현과 탐색은 `medium`(구현 xhigh 는 4배 넘게 걸리고 명세 밖까지 짓는다). 사용자가 지정했으면 그것을 적는다

## 3. 넘긴다

Agent 도구로 `subagent_type: "qwen-delegate:qwen-worker"` 에 브리프를 넘긴다. 위임은 5~45분 걸리므로 백그라운드로 두고 다른 일을 계속한다.

## 4. 받는다

서브에이전트는 확인된 지적과 틀리거나 미확인인 지적을 나눠 돌려준다. 사용자에게는 확인된 것을 중심으로 전하고, 구현은 worktree 의 diff 를 받아들이기 전에 직접 훑는다. 서브에이전트가 `output_limit` 이나 설정 경고를 돌려주면 사용자에게 `node ${CLAUDE_SKILL_DIR}/scripts/delegate.mjs setup` 과 README 의 설정 절을 안내한다.

# Qwen 위임

목적은 **Claude 로 가는 토큰을 줄이는 것**이다. 파일을 읽고 추적하는 일은 Qwen 이 하고, 지적 확인은 `qwen-delegate:qwen-worker` 서브에이전트(Sonnet)가 한다. 이 대화(메인)가 쓰는 토큰은 브리프와 결과 전달뿐이어야 한다.

## 메인이 하지 않는 일

메인이 아래를 하면 위임해서 아낀 토큰을 다시 쓴다(실측: 메인이 브리프를 쓰려고 코드를 읽고 지적을 다시 추적해 Opus 몫이 25만 토큰이 됐다).

- **파일을 열거나 검색하지 않는다.** 브리프는 이 대화에 이미 있는 정보와 사용자 요청으로만 쓴다. 대상 경로를 모르면 사용자가 말한 이름 그대로 적는다 — 위치는 서브에이전트가 찾는다.
- **돌아온 지적을 다시 추적하지 않는다.** 서브에이전트가 확인함·틀림·미확인으로 나눠 온다. 그대로 전한다. 사용자가 특정 지적을 더 보자고 할 때만 그 자리를 연다.
- `delegate.mjs` 를 직접 돌리지 않는다.

## 1. 맡길지 정한다

맡기는 일 — 직접 하면 여러 파일을 읽고 도구를 10번 넘게 부를 일:

| 종류 | 상한 | 실측 (Claude 로 간 토큰, 직접 → 위임) |
|---|---|---|
| 리뷰 | 대상과 시나리오를 정해 줄 수 있으면 함수 1개부터 5~6 파일과 관련 SQL 추적까지 | 81만 → 39만, 98만 → 36만 |
| 탐색 | "X 가 어디서 쓰이나", 모듈 구조 요약 | — |

직접 하는 일:
- **구현.** 실측 81만 → 99만으로 오히려 늘었다 — Qwen 의 diff 를 검토하고 고치는 비용이 직접 짜는 비용보다 컸다.
- 도구 몇 번이면 끝나는 일 — 서브에이전트 기동비(새 토큰 약 4.5만)가 더 크다.
- 검증이 다시 하는 것과 같은 일 — "모듈 전체 검토"처럼 열린 리뷰(먼저 사용자와 범위를 좁힌다), 설계 결정, 보안의 최종 판정.
- DB·통합 환경·비밀값·실행 중인 서비스가 있어야 확인되는 일.

## 2. 브리프를 쓴다

서브에이전트와 Qwen 은 이 대화를 보지 못한다. 대화에 있는 것만으로 짧게:
- 절대 경로 작업 디렉토리
- 대상(파일·함수·기능 이름 — 아는 만큼)과 그 값이 어디에 쓰이는지(대화에 있으면)
- 검토할 시나리오: "어떤 상황에서 무엇이 틀릴 수 있나" — 실측에서 이 한 줄이 적중률을 갈랐다
- 보고 언어
- effort: 결함을 찾는 리뷰는 `xhigh`, 탐색은 `medium`. 사용자가 지정했으면 그것

## 3. 넘기고 전한다

Agent 도구로 `subagent_type: "qwen-delegate:qwen-worker"` 에 브리프를 넘긴다. 5~15분 걸리므로 백그라운드로 두고 다른 일을 계속한다. 돌아온 요약을 사용자에게 그대로 전한다. 서브에이전트가 설정 문제(`output_limit`, `warnings`)를 알리면 `node ${CLAUDE_SKILL_DIR}/scripts/delegate.mjs setup` 과 README 의 설정 절을 안내한다.

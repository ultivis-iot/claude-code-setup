# 서브에이전트 모델 선택

`Agent` 도구로 서브에이전트를 띄울 때 작업 난이도에 맞는 모델을 고르고 `model` 파라미터를 **항상 명시**한다. 생략하면 부모 모델을 물려받아 전부 같은 모델로 돌아가고 한도를 빨리 소진한다.

| 모델 | 쓰는 작업 |
|---|---|
| `opus` | 설계 판단이 필요한 새 구현, 보안 표면(인증·세션·권한), 상태 머신·동시성, 실증·ux-review, 원인 불명 결함 추적 |
| `sonnet` | 정해진 계약대로 하는 구현, AI 리뷰 반영·review-cycle 마무리, 화면 재구성, 테스트 보강, 마이그레이션 |
| `haiku` | 기계적인 작업 — 문서 표 정리, 라벨·배지 추가, handoff 갱신, 단순 필드 추가, 파일 이동 |

- 띄우기 전에 그 Task가 어느 칸인지 먼저 정한다. 애매하면 `sonnet`.
- 한 Story의 Task들을 병렬로 띄울 때도 Task마다 따로 판단한다. 같은 Story라고 같은 모델을 쓰지 않는다. Story Task는 `/ult-story-run` 실행 요약의 Model·Effort 값을 따른다.
- 검증 서브에이전트(intent/doc/security/standards/test validator)도 같은 기준으로 고른다.
- Codex에는 이 모델 이름이 없다. Codex에서는 위임 권한과 실행 환경의 모델 설정을 따른다.

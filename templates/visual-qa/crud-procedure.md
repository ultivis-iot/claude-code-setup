# CRUD 플로우 테스트 절차

해당 라우트에 CRUD UI가 있는 경우, **새 항목을 생성하고 그것만 수정/삭제**하여 전체 플로우를 검증합니다.

## Create (생성)
- "새로 만들기", "추가", "Create", "Add" 등 생성 버튼 클릭
- 폼/모달이 열리면 스크린샷 → 테스트 데이터 입력
- 테스트 데이터 규칙:
  - 텍스트 필드: `[QA-TEST] ` 접두어 + 타임스탬프 (예: `[QA-TEST] 20260206-143022`)
  - 숫자 필드: 기본값 또는 최소값
  - 선택 필드: 첫 번째 옵션
  - 필수 필드만 입력, 선택 필드는 빈칸 허용 시 스킵
- Submit → 성공/실패 확인 → 스크린샷
- 생성된 항목의 식별 정보(ID, URL, 리스트 내 위치) 기록

## Read (조회)
- 생성된 항목의 상세 페이지 또는 리스트 내 해당 행 확인
- `[QA-TEST]` 접두어로 방금 생성한 항목을 식별
- 스크린샷

## Update (수정)
- 생성된 항목의 "수정", "편집", "Edit" 버튼 클릭
- 텍스트 필드 하나를 `[QA-TEST-EDITED]`로 변경
- Submit → 변경 반영 확인 → 스크린샷

## Delete (삭제)
- 생성된 항목의 "삭제", "Delete", "제거" 버튼 클릭
- 확인 다이얼로그가 나오면 확인/삭제 버튼 클릭
- 리스트에서 해당 항목이 사라졌는지 확인 → 스크린샷

## 안전 규칙
- **기존 데이터는 절대 수정/삭제하지 않음** — 오직 `[QA-TEST]` 접두어가 있는, 이 세션에서 직접 생성한 항목만 대상
- 생성 실패 시 → 수정/삭제 단계 건너뛰고 FAIL 기록
- 수정/삭제 대상을 찾을 때 반드시 `[QA-TEST]` 텍스트로 식별 확인 후 진행
- CRUD UI가 없는 라우트(대시보드, 설정 등)는 이 단계 건너뜀
- **Delete 실패 시 잔여 데이터 경고**: 삭제에 실패하면 해당 항목 정보(라우트, 항목명, ID)를 `crud_residual` 목록에 기록하고, Phase 7에서 사용자에게 수동 정리 안내

## 결과 보관 형식
```
{ route, create: ✅/❌, read: ✅/❌, update: ✅/❌, delete: ✅/❌/⚠️(잔여), error_detail, residual_item }
```
